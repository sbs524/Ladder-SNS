**브랜치**: `feat/dashboard-real-metrics` (이어서)

### 확정: 요금제·크레딧·모델

전부 **[`과금_및_지표_정의.md`](과금_및_지표_정의.md)** 로 옮겼다. 기획서 6장(과금)을 대체한다.
요약만:

- **Free + Plus 2단계.** 기획서의 Business 티어 삭제 — 수요 확인 전까지 안 만든다
- **Plus ₩14,900/월** (연 ₩149,000). 연동 채널 Free 2 / Plus 5
- **크레딧 소모량 인하**: 리포트 10→**5**, 심층 3→**2**, 질문 1 유지. 팩 가격은 유지
- **모델은 `gemini-3.7-flash` 단일**, 환경변수화
- **원장은 MVP에서 "성공 시 차감"** — 홀드/커밋/릴리즈 3단계 보류 (append-only는 유지)

**기획서를 뒤집은 이유**: 기획서 6.2의 "원가의 3~5배" 규칙이 성립하지 않는다. 리포트 1건
실제 원가가 **약 29원**인데 기획서 가격은 1,000원 — 34배다. AI 원가가 무시할 수준이라
가격 결정 근거가 못 된다. 그리고 **진짜 고정 원가는 AI가 아니라 YouTube Data API quota**
(일 10,000 units)이고, 그건 분석 횟수가 아니라 **연동 채널 수**에 비례한다. 그래서 요금제에서
가장 중요한 줄은 "월 리포트 N회"가 아니라 "연동 채널 N개"다.

### 추가: `GET /api/metrics/insights` (`src/server/insights.ts`)

AI 분석 화면의 목업(`ENGAGEMENT_DEEP_METRICS`, `CONTENT_FORMAT_STATS`)을 대체할 실계산.
공식은 전부 `과금_및_지표_정의.md` §5에 있고 코드 주석이 그리로 가리킨다.

**해결한 두 가지 어려운 항목**

- **`peakTime`** — YouTube Analytics API에 **시간(hour) 디멘션이 없어서** 가져올 수 없다.
  대신 우리 DB의 업로드 이력으로 집계한다: 발행 후 3일 조회수를 KST 시간대 4구간으로 나눠
  **중앙값 배수**를 낸다. 중앙값을 쓰는 건 대박 영상 하나가 슬롯을 왜곡하기 때문
- **`viralityScore`** — API 지표가 아니라 우리가 정의했다. "구독자 밖으로 얼마나 퍼졌나"를
  도달 배수(0.35) + **비구독자 시청 비중(0.30)** + 참여율(0.20) + 공유율(0.15)로 계산.
  비구독자 비중은 이미 수집 중인 `subscribed_status` 브레이크다운에서 나온다

**표본이 부족하면 숫자를 내지 않는다.** 영상 12개 미만이면 `peakTime`을 계산하지 않고,
슬롯/포맷당 3개 미만이면 순위에서 뺀다. 표본 수를 응답에 같이 실어서 UI가 표시하게 한다.
근거 없는 숫자는 목업과 똑같기 때문이다.

### 아직 수집이 필요한 것 (친구 담당)

| 필요한 것 | 쓰이는 곳 |
|---|---|
| `videosAddedToPlaylists` 지표 + 컬럼 1개 | `saveRate` (현재 `null` 반환 중) |
| `video` 디멘션 브레이크다운 (`shares`) | 포맷별 `avgSavesOrShares` |

나머지 항목은 전부 이미 쌓이는 데이터로 계산된다.

`AIAnalysisModal.tsx`(802줄)를 이 엔드포인트에 배선하는 것. 계산은 끝났고 화면만 남았다.

### 추가: `GET /api/metrics/overview`

**새 파일** `src/server/metrics.ts`. 대시보드 화면 하나가 필요로 하는 모든 숫자를 한 번의
요청으로 돌려준다.

| 파라미터 | 값 | 기본값 |
|---|---|---|
| `range` | `7d` \| `30d` | `7d` |

응답에 담기는 것:

- `totals` — 통합 팔로워, 기간 조회수, 평균 참여율, 직전 동기간 대비 증감률
- `platforms[]` — 플랫폼 4개 전부. 연동 안 된 플랫폼은 `connected: false`로 내려간다
- `chart[]` — 기간 내 **날짜별 플랫폼별 조회수**. 하루 단위로 빈 날도 0으로 채워서 내려준다
- `recentPosts[]` — 최근 동기화된 콘텐츠 12건 (제목·발행일·조회·좋아요·댓글·원본 링크)

**왜 엔드포인트를 하나로 묶었나**: 화면이 한 번에 그려지는데 요청을 4~5개로 쪼개면 로딩 상태가
따로 놀고 폭포수 요청이 된다. 대시보드는 "한 화면 = 한 요청"으로 간다.

### 확정한 계산 규칙

여기 적은 정의가 화면에 뜨는 숫자의 유일한 출처다. 바꾸려면 이 문서도 같이 고친다.

| 지표 | 정의 |
|---|---|
| **참여율** | `(좋아요 + 댓글 + 공유) / 조회수 × 100`, 선택 기간 합계 기준 |
| **기간 조회수** | `youtube_channel_daily_metrics.views`의 기간 합계 |
| **증감률** | 현재 기간 조회수 vs **직전 동일 길이 기간** 조회수 |
| **팔로워 증감** | 기간 내 `subscribers_gained - subscribers_lost` |
| **통합 팔로워** | `youtube_channel_profiles.subscriber_count`의 현재 스냅샷 합계 (기간 무관) |

**비교 기준이 0이면 증감률을 `null`로 내리고 화면에 `–`를 띄운다.** 0에서 늘어난 걸
`+100%`로 표시하면 거짓말이 된다.

> **기획서와 달라진 용어**: 기획서와 기존 UI는 "도달·노출(impressions)"이라고 썼지만 실제로
> 표시하는 값은 **조회수(views)** 다. `youtube_channel_daily_metrics.impressions` 컬럼은 있지만
> YouTube Analytics에서 항상 채워지는 값이 아니라서 신뢰할 수 없다. UI 라벨도 "조회수"로 바꿨다.

## 그 이전 — 기획서 작성 이후 이미 반영된 변경

기획서 v1(2026-08-21) 이후 코드에 들어갔지만 문서에 반영되지 않았던 것들. 코드를 읽어서
역으로 정리했다.

### 인증 — 자체 구현 대신 Supabase Auth (기획서 Phase 1 대체)

기획서는 `users` 테이블 + argon2id 해시 + 자체 세션을 계획했지만, **Supabase Auth로 갔다.**

- 이메일 **OTP**(6자리, 5분 만료) 가입·로그인 + Google OAuth
- `auth.users` ↔ `public.profiles` 연결
- HttpOnly · SameSite=Lax 세션 쿠키, 세션 갱신, 로그아웃
- 마이페이지: 프로필 수정, 아바타 업로드, 회원탈퇴

**영향**: 비밀번호 자체가 없어졌으므로 `src/passwordPolicy.ts`와 그 테스트는 **현재 아무데서도
쓰이지 않는다.** 기획서 Phase 1의 "서버측 비밀번호 정책 검증" 항목도 무효. 삭제 여부 결정 필요.

### 배포 — VPS 대신 Render (기획서 4장 "결정 필요" 항목 2 해소)

- `laddersns.com` 단일 Render Node 웹 서비스. 프론트·API 분리(`app.` / `api.`) 안 함
- `main` push 시 자동 배포. 헬스체크 `/api/health`
- Redis 없음. 워커는 별도 프로세스가 아니라 **웹 프로세스 안의 `setInterval`**
  (`YOUTUBE_SYNC_WORKER_ENABLED=true`일 때만)
- 도메인도 `laddersns.io` → **`laddersns.com`** 으로 확정

> ⚠️ 인스턴스를 2개 이상으로 늘리면 워커가 중복 실행된다. 스케일아웃 시 재설계 필요.

### YouTube — 읽기 전용 계획에서 쓰기까지 확장 (기획서 범위 초과)

기획서 Phase 2는 "채널 정보 가져와 저장"까지였지만 실제로는 더 갔다.

- 토큰 **AES-256-GCM** 암호화 저장, state HMAC 서명, 자동 갱신, 해제 시 Google revoke
- Data API v3 + Analytics API v2 동기화, 잡 큐(`platform_sync_jobs`)
- 댓글 동기화 + **SSE 실시간 스트림**
- **쓰기 기능**: 영상 제목·설명 수정·삭제, 댓글 답글·숨기기·삭제 ("원본 데이터" 페이지)

> ⚠️ 쓰기를 위해 스코프가 `youtube.readonly` → `youtube.force-ssl`로 바뀌었다.
> **그 전에 연결한 채널은 재연동(재동의)해야 쓰기 기능이 동작한다.** 기존 사용자 마이그레이션 미처리.

### Google OAuth 게시 상태 — 아직 "테스트"

연동 시 "Google에서 확인하지 않은 앱" 경고가 뜨는 건 정상이다. 테스트 사용자로 등록된
계정이면 `계속`을 눌러 진행하면 된다.

> 🔴 **테스트 상태에서 발급된 refresh token은 7일 후 만료된다.** 그러면 동기화가 멈추고
> `platform_oauth_grants.status = 'requires_reauth'`로 바뀐다. 코드 버그가 아니라 Google 정책이다.
> 프로덕션 게시 + 앱 검증이 필요하고, 그 전제로 **개인정보처리방침·이용약관 페이지**가 있어야 한다
> (기획서 Phase 7 항목이지만 이것 때문에 앞당겨야 한다).
